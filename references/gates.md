# 六关细则

总控按关 1 到关 6 顺序走。用户每关只做选择题。阶段分界：关 1–3 是设计探索——样稿可由出样者直做、一次性、选后即弃、不进仓库；关 4 起才进真仓库，此后走该项目既有的开发与验收流程。

构图规矩（主角、颜色、出血、标杆、构图问答）在 `composition.md`。出样者、交付判定通则、逐项自查表的全文在 `sampling-and-vendors.md`。字号阶梯、字体栈、嵌套圆角、克制三条在 `type-and-tokens.md`。先生图备选路在 `image-first.md`。工作区/后台页在 `admin-workspace.md`。关 5 与关 6 的全文在 `review-and-rework.md`（本文件这两关只留要点）。Brief 模板在 `../templates/brief.md`，修改单模板在 `../templates/change-request.md`。

## 关 1 需求 Grill

执行本技能的 agent 问，用户答。产物：`brief.md`（套用返工控制模板第一页，即 `../templates/brief.md`）。

**第 0 步（硬步骤）：先核现状再填 brief。** 预填 brief 前先核对该项目已有规格/功能清单，产出或更新《现有功能清单》作基线。页面数、功能数以基线为准，不凭印象预填。

**项目类型先判定：** 新建型直接走 5 题。改版型先加一题三选一——「保留结构改样式 / 只保功能清单、界面重做 / 全新设计」，并在 brief 里加「现状基线」一节（功能清单为准、附现状截图）。关 2 的方向从基线出发，不被旧样式框住。

固定必答 5 题（带推荐答案，用户点头或只改一处即可）：

1. 项目形态：网页 / App 内页 / 落地页？设备：手机优先还是桌面优先？产物类型：真页面 / 宣传物料（静图、动画、Bento）/ 两者都要？含宣传物料时，同时写明尺寸、时长和故事拍子
2. 本轮页面清单：只做哪几页，明确不做哪几页
3. 参考：1-3 张图/链接，各说一句喜欢哪点
4. 真内容：标题、正文、数据由用户给，没有就先标占位并记账
5. 成功标准：这一版做到什么样算过（如：手机上不溢出、首屏看懂是干什么的）

定版写明 5 题带推荐答案，没有给出每题的默认选项。推荐从已核的《现有功能清单》和用户已经给出的材料来，写进 brief 的推荐答案位。

**未来功能 UI 预留：** brief 加一栏「未来功能 UI 预留」：本轮只做 UI、功能后做的部分，口径二选一写明——默认按已可用的样子设计、不灰置占位；功能开发另行立项，不在本轮范围。

**逐格内容配额（硬步骤，口径见 `density.md` 第一节）：** brief 里每格一张配额表——信息元素逐项列明 + 元素数下限（装饰与空白不算元素）。没有配额表的 brief 不算填完。配额由内容决定：内容撑不起一格的，不独立成格。

本关完成：`brief.md` 已按模板填完（含逐格内容配额表）；第 0 步基线已核对；新建或改版分支已走完；5 题都有答案，且用户已点头或只改了一处；未来功能栏已写明。用户说得清要什么，才进关 2。

## 关 2 方向小样

Agent 出，用户选。改版型的方向从关 1 的现状基线出发，不被旧样式框住。

出样分工、交付判定通则、逐项自查表，按 `sampling-and-vendors.md` 执行。默认由执行本技能的 agent 本人出样（自出）。本关必须同时满足下面几条：

- 执行本技能的 agent 调用：UI UX Pro Max（推荐配合，若环境已安装；未安装时按本技能 references 的对应口径直接执行）定结构/组件选型 + Taste（推荐配合，若环境已安装；未安装时按本技能 references 的对应口径直接执行）定原创方向（脱离参考图时）。
- **技能调用硬检查：** 出样简报必须写明本轮调用哪个技能、读了哪份 SKILL.md，交付时由执行本技能的 agent 核对。技能管审美出处（色板/方向要有来源、可追溯）。同时简报附「交付前 brief 逐项自查表」，出样者逐项打勾——技能管审美、自查表管规格遵循，两者不可互相替代。表的行见 `sampling-and-vendors.md`。
- **先定标杆：** 出样前定 2–3 张标杆图，存放在 `explorations/benchmarks/`，来源见 `composition.md` 第五节。
- 一次出 3 个方向，只做首屏/首页一屏，不做完整页；3 版并排对比图交付。每版按 `composition.md` 的【通用】条摆放，并写明「第一眼应该看到什么」。对比图里同时放上标杆。
- **交付格式：** 默认 HTML + 截图（出图通道固定为执行环境可用的浏览器截图工具（如 Playwright/Chromium），或出样者自带截图）；无截图条件时必须明示，并逐个打开 HTML 逐项文字核验，不许以「对比图」名义假装有图。
- **数据自洽：** 验收清单加一条——样稿内数据互相对得上（进度比例、时间戳、百分比、波形长度同一口径）；最强做法是单一数据源程序生成、其余画面从它派生，出样要求里优先写明。
- 用户只做一件事：选 1 个，或说「A 的版式 + B 的配色」这种组合选法。
- 未选中的 2 版存档 `explorations/`，不删，日后回看不用重生成。

直出小样排版平庸、方向定不下，或用户想先看图定方向时，走 `image-first.md`。那不是默认路，关 2 主线仍是技能直出。

产物：`explorations/` 下 vA、vB、vC + 对比截图。

本关完成：3 个首屏方向已交付，且过 `sampling-and-vendors.md` 的字节校验、brief 逐项自查和数据自洽；用户已选出 1 个方向或一个组合；未选中的 2 版已存档。

## 关 3 锁定 Design Tokens

把选中方向抽成锁定表：配色 hex、字体、字号阶梯、圆角、间距（8 的倍数）、按钮/卡片/导航样式。字号阶梯的档位、三类改法、中文字体栈、嵌套圆角、克制三条，以 `type-and-tokens.md` 为唯一数字出处，本关不另写一套。

- 落成文件：`design-tokens.md` + 代码里的 CSS 变量 / tailwind theme，全项目只认这一份。4a 真页面和 4b 宣传物料都引用这同一个文件，不另抄一份。
- 方向里有超大展示数字时（纪念碑数字、hero 统计），按 `type-and-tokens.md` 的展示档锁定，不当单点例外处理。
- **tokens 双轨制：** 锁定源以复核者从样稿代码逐值提取的版本为准（能抓出文案口径、两版不一致这类偏差）；同时要求出样者自带一份 tokens 清单作意图参考。两者差异逐条裁定，决定补充进锁定版的走 `CHANGELOG-UI.md` 留痕。
- 规矩：锁定后改 tokens = 全站变更，必须用户明确说「解锁改 X」并记一行变更记录。
- 锁定后把这句写成对后续修改都有效的约束：`以上为锁定项，除非我明确说解锁，否则任何修改都不得变更。`
- 这一步就是 tokens 在代码里就是设计系统，不需要再在设计工具里维护第二份。

产物：`design-tokens.md`（已批准版）。

本关完成：用户确认锁定表；提取版与出样者清单的差异已逐条裁定；要补进锁定版的已写入 `CHANGELOG-UI.md`。

## 关 4 单页实现

Agent 写，用户不碰代码。分两线，4a 永远是母版，4b 只吃 4a 的产物。

### 4a 真页面（母版）

顺序：先做透 1 个标杆页 -> 用户确认 -> 其余页复制标杆页的组件与 tokens。按 `composition.md` 的【通用】【页面】条执行：铺满视口，用真内容，覆盖全部状态，桌面和 390 手机都成立。数据只来自一个数据源文件（如 `data.json`），页面从它派生。

**格随内容定（口径见 `density.md` 第二节）：** 先列全部格的内容清单、按关 1 配额定格子大小与数量，最后才排网格；禁止先画等大网格再填内容。每格在实现里标 `data-cell="<格名>"` 供关 5 量密度。两轮仍达不到配额的格必须缩小、合并或取消。

- 组件化硬要求：按钮/卡片/标题栏必须是可复用组件，禁止逐页复制粘贴样式。后面改一处，全站变。
- 动效在此关后半段才加：Emil / animate 系列技能（推荐配合，若环境已安装；未安装时按本技能 references 的对应口径直接执行），只加在已定版的版式上。
- 做仪表盘、数据表、表单时，先按 `admin-workspace.md` 的临时口径。成套中后台轨道未立。

### 4b 宣传物料（仅当产物类型含宣传物料）

- **前提**：4a 标杆页已经定版。宣传物料不早于 4a 开工。
- **生产线**：使用 Stageshow（若已安装），按它的流程 look → story → example → screen → choreograph → rehearse 走。
  - look：把 4a 的组件放进 Stage，并引用同一份 tokens.css 和数据源；不用 kit 自带外观，也不自己发明样式。
  - example：复制最接近的金样例，取用它的画幅、裁切、卫星和节拍。
  - 设备、窗口：用 kit 的真实几何。
- **构图**：按 `composition.md` 的【通用】【物料】条执行。
- **动画**：一镜到底，先定封面帧，用虚拟时钟逐帧录制。尺寸、时长、编码按 brief 写死。
- **手机版**：宽画面另做 358 宽的手机版，要重新设计，不是压缩。
- **未安装 Stageshow 时**：用 4a 页面加时间参数逐帧渲染，再用 Playwright 截图、ffmpeg 合成。手机外框用 4a 的设备组件，不临时手画。
- **对账（硬步骤）**：4b 做完，从 4b 代码重新提取 tokens，与锁定版逐条对比。差异逐条裁定：要么改回锁定值，要么由用户说「解锁改 X」后写入 `CHANGELOG-UI.md`。没对完账不算交付。
- **代码位置**：放在 `<project>/promo/`，成品放 `promo/dist/`。

产物：4a 标杆页 + 组件清单，代码进 `<project>/src/`，组件与 tokens 为准；4b 的 `promo/` 源码与成品。

本关完成：用户已确认标杆页；按钮、卡片、标题栏是可复用组件；其余页用的是这份组件和已锁定的 tokens。动效只出现在已定版的版式上。含宣传物料时，4b 成品已交付，且 tokens 对账已完成。

## 关 5 截图验收 + 修改单循环

要点如下，条文、话术和回执格式以 `review-and-rework.md` 为准，填空用 `../templates/change-request.md`。

- 每版交付必须带：桌面 + 手机（默认 390x844）双截图 + 页面文字重读核对。
- 构图验收：答 `composition.md` 第六节问答，跑标签碰撞检测，把屏上数字反读出来与数据源比对，并与标杆并排截图。
- 密度验收（硬步骤，口径见 `density.md` 第三、四节）：按实际网格写 `density-layout.json`，跑 `scripts/density_check.py` 出 `density.json`；任一格 FAIL 即本轮不合格。构图问答每题必须引用读数或坐标作证据，只写「是」无效；density.json 原文进 review 与 DONE。
- 4b 物料另交：展示宽度和 358 手机宽度的联系表、封面帧，以及 Stageshow 影片闸门的结果（未安装时写明替代检查）；视频用 ffprobe 核对规格。
- 修改单：一轮一类、≤5 条、指明基于哪个版本、列「不要改」清单。
- Agent 改完回：新截图 + 逐条对应清单 + 明确没改什么；对不上不算交付。
- 版本：`name-v1 / v2 / v3` 另存不覆盖，定版标母版；回退随时能回到上一版。
- 循环上限：默认 2-3 轮，超了先停下问「是方向错了还是细节没完」——方向错回关 2。
- 字号、间距、颜色这类小细节，三条全满足时走微调快车道，不走整轮修改单。条件与话术见 `review-and-rework.md`。

产物：每轮 `reviews/review-vN.md`（截图 + 清单 + 结论）。

本关完成：当轮回执和修改单逐条对得上，并写明没改什么。默认停在 2-3 轮；超过则已经判定是回关 2，还是继续收细节。

## 关 6 审查上线

要点如下，三秒 / 换皮 / 480px 缩略的判词、180px 尺度、AI 味条目，以 `review-and-rework.md` 为准。

- Impeccable（推荐配合，若环境已安装；未安装时按本技能 references 的对应口径直接执行）：audit / polish（对齐、对比度、可访问性、溢出）。
- Hallmark（推荐配合，若环境已安装；未安装时按本技能 references 的对应口径直接执行）：sloplint 查 AI 味（模板感、假渐变、卡片套卡片）。
- Apple Design / mobile-native（推荐配合，若环境已安装；未安装时按本技能 references 的对应口径直接执行）：仅当做 iOS 向 App 页时加。
- 评审小测试三条都做：三秒测试、换皮测试、缩到 480px 仍认得出。
- 过关才部署。部署后公网打开实测一次，不以本地截图代替。

本关完成：Impeccable 与 Hallmark 已跑完（推荐配合，若环境已安装；未安装时按本技能 references 的对应口径直接执行），评审小测试过关，公网实测已做一次。未过关不部署。
