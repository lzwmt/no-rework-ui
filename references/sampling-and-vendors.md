# 出样者与交付

关 2 派单、技能核对、逐项自查、数据自洽和交付验收以本文件为准。三个方向怎么选、何时改走先生图，见 `gates.md` 关 2 与 `image-first.md`。

## 出样顺序

出样顺序：默认由执行本技能的 agent 本人出样（自出）。可选把方向探索外包给本环境可用的其他 agent 或设计工具。外包时简报须写明所用技能、自带 tokens 清单；交付以文件落盘可读为准，并做逐项自查、数据自洽。产出按交付判定通则严验。要比审美或用户点名时才多家同题，分别记录各家产出与结论。

## 技能调用硬检查

出样简报必须写明本轮调用哪个技能、读了哪份 SKILL.md，交付时由执行本技能的 agent 核对。技能管审美出处（色板/方向要有来源、可追溯）。

关 2 的调用是：UI UX Pro Max（推荐配合，若环境已安装；未安装时按本技能 references 的对应口径直接执行）定结构/组件选型；脱离参考图时，Taste（推荐配合，若环境已安装；未安装时按本技能 references 的对应口径直接执行）定原创方向。外包时简报还要写明用技能，并自带一份 tokens 清单（意图参考，不是锁定源；锁定源见 `gates.md` 关 3）。

技能核对（和下面的自查表分开打，不能互相替代）：

- [ ] 简报写明本轮技能名
- [ ] 简报写明读了哪份 SKILL.md
- [ ] 色板和方向有来源，能追溯
- [ ] 执行本技能的 agent 在交付时核对过上面三项

## 交付前 brief 逐项自查表

简报附上本表，出样者逐项打勾。行就是 `../templates/brief.md` 的栏目，加上定版写进验收清单的数据自洽一条。定版没有另给一张现成的表。

- [ ] 第 0 步已核对《现有功能清单》；页面数、功能数以基线为准
- [ ] 项目类型已判定（新建型 / 改版型）
- [ ] 改版型已选「保留结构改样式 / 只保功能清单、界面重做 / 全新设计」，且有现状基线（功能清单为准、附现状截图）。新建型打「不适用」
- [ ] 项目（一句话）
- [ ] 给谁用
- [ ] 设备（手机优先时含 390x844 / 桌面优先 / 两者都要）
- [ ] 页面清单：本轮做哪些，明确不做哪些
- [ ] 参考：1-3 张图或链接，各有一句喜欢哪点
- [ ] 不想要
- [ ] 真内容已给出；没有的已标占位并记账
- [ ] 本轮只做
- [ ] 关 1 的 5 题都有答案，含成功标准；推荐答案用户已点头或只改了一处
- [ ] 未来功能 UI 预留已写明。未另选口径时：按已可用的样子设计、不灰置占位；功能开发另行立项，不在本轮范围

## 数据自洽与单一数据源

验收清单加一条：样稿内数据互相对得上（进度比例、时间戳、百分比、波形长度同一口径）。最强做法是单一数据源程序生成，其余画面从它派生。出样要求里优先写明要单一数据源。

## 交付判定通则

对所有出样者：

一切交付以文件落盘且可被复核者读到为准，不认口头声称。交付 = 复核者读到文件字节并校验通过（实读/md5），任何口头或文字「已交付」声称不算。外部样稿同样过 brief 逐项 + 数据自洽验收，「概念更丰富」不能抵规格缺失。

验收时逐条看：

- [ ] 复核者实读了文件，或做了 md5 校验
- [ ] 外部样稿已过上面的 brief 逐项自查和数据自洽

## 交付格式

默认 HTML + 截图。出图通道固定为执行环境可用的浏览器截图工具（如 Playwright/Chromium），或出样者自带截图。无截图条件时必须明示，并逐个打开 HTML 逐项文字核验，不许以「对比图」名义假装有图。

一次出 3 个方向，只做首屏/首页一屏，不做完整页。3 版并排对比图交付。

用户选定之前，稿留在关 1–3 的设计探索里，不进仓库。未选中的 2 版存档 `explorations/`，不删。
