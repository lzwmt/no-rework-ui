# Astryx 路线（中后台成套轨道）

Meta 开源设计系统 Astryx（React 19 + StyleX，150+ 无障碍组件，MIT，Beta）是本工作流的中后台成套轨道：新建 React 19 项目的后台/工作区页默认走它实现。本文件是关 1 判定、关 2 出样、关 3 锁定、关 4 实现、关 5 验收在该路线下的全部口径；未提及的关口按主线原口径执行。

依据（2026-11-08 同题试跑）：同一「任务看板后台」题目，Astryx 版与纯手写版（零 UI 库）同场对比，两版构建均过、内容逐字一致、数据同源。关键读数：页面净代码 457 行 vs 848 行（−46%，省的几乎全是 CSS：25 行 vs 535 行）；产物 JS 5.1×、CSS 41×（全部组件样式打入）；CLI 查组件契约帮执行者避开三处必错点。完整证据在试跑 RESULT（组件清单、构建输出、问题原文）。

## 关 1：路线判定（与 5 题同轮定死，逐页标明）

- 后台/工作区页（仪表盘、数据表、表单、设置）**且**新建 React 19 项目（或愿按 React 19 新建）→ Astryx 路线。
- 前台页 / 落地页 → 手写路线（视觉独特性优先、体积敏感），不走本文件。
- 原生 App 页（Expo / React Native）→ 走原生生态；小程序/多端 → 走 uni-app 路线（见 `uni-app-route.md`）。Astryx 依赖 react-dom 与 CSS，原生壳无 DOM/CSS，技术上接不进，不判定。
- 一单可混合多路线（如前台手写 + 后台 Astryx），brief 逐页标明路线，不许实现到一半才发现栈不对。
- 面向公网的后台页例外：产物体积数（见关 5 读数口径）在判定路线时先摆给用户裁定，默认不走 Astryx；内部/自用后台知情即可。

## 关 2：出样变体

后台页不出 3 个自由方向：改为在 Astryx 现成主题（如 theme-neutral 等）里选 1 套 + 定深浅模式，出样 = 用选中主题出标杆页雏形，用户确认主题与模式即过关。前台页仍按主线出 3 个方向。一单混合路线时两类页面分别出样、分别选。

## 关 3：锁定对象变体

锁定对象 = 主题包 + 深浅模式 + 少量覆盖变量，不从零手写全套 tokens。`design-tokens.md` 记这三样及与主题变量的映射；覆盖变量仍按双轨制提取核对（锁定源以复核者从代码逐值提取版为准）。改主题 = 解锁级变更，走 `CHANGELOG-UI.md` 留痕。

## 关 4：实现规矩（硬规矩）

- 栈：Vite + React 19 + TypeScript。依赖 `@astryxdesign/core` + `@astryxdesign/theme-<主题>`，开发依赖 `@astryxdesign/cli`。**版本钉 0.7.11**（Beta，0.x 小版本可 breaking change）；升级先做同题小试、验过再换，不在项目里跟随 latest。
- 组件优先：有 Astryx 组件的部位必须用组件。手写替代必须在交付报告里逐个列明部位与原因，无清单视为未按轨道执行。本工作流「组件化硬要求」在本轨道的落地形态就是这份组件清单。
- 先查契约再写：写每个组件前先查 props 契约——`npx astryx component <名> --dense`（省 token 读法，默认用它），或 `npx astryx manifest --json` / MCP。不许凭 React 习惯猜。试跑实测三大猜错点：Table 列宽须 `proportional()` / `pixel()` helper 不是数字；TextInput 的 onChange 直接给 string 不是事件；Dialog 做表单须 `purpose="form"` 防点遮罩误关。
- 样式纪律：外观走主题 token。手写 CSS 只许做主题不管的文档根级事项（如字体栈、高度链），且逐行说明用途。主题样式表导入顺序（reset → astryx → theme）不可换，错了整体失效且无报错。
- 中文化：Astryx 自带 zh-CN locale，须显式挂 InternationalizationProvider 并在 tsconfig 开 resolveJsonModule，否则 DateInput 等组件占位符是英文。
- 前台不混用：同项目前台页不许顺手套 Astryx 组件图省事；两条线只共享数据与文案口径，各走各的 tokens。

## 关 5：加两项读数（只报告，不新设门槛）

1. 组件清单核对：交付报告列实际用的 Astryx 组件与全部手写替代部位，复核者逐项核理由是否成立；理由不成立的按修改单打回换组件实现。
2. 产物体积读数：build 产物 JS / CSS 大小（含 gzip）写进 review。异常膨胀（如重复引入两套主题）才打回。面向公网的页面例外：按关 1 裁定口径复核，超了即打回。

## 不走本路线的边界（写死）

- 高度定制的视觉页（品牌页、4b 宣传物料）不走，视觉方差正是本路线要消除的东西，反过来也是它的上限。
- 现有非 React 19 项目不迁移、不混入；要试只在新项目。
- 手写路线保留为随时可退的基线：Astryx 轨道出问题（Beta 变动、体积不可接受、组件覆盖不了核心场景），整单退回手写路线，不在半路缝补。
