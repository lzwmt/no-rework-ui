# uni-app 路线（小程序/多端轨道）

uni-app（DCloud，Apache-2.0）是本工作流的小程序/多端轨道：目标端含小程序、或需小程序+H5+App 多端同发的项目默认走它实现（Vue3 + Vite，一套代码多端编译）。本文件是关 1 判定、关 2 出样、关 3 锁定、关 4 实现、关 5 验收、关 6 上线在该路线下的全部口径；未提及的关口按主线原口径执行。

依据（2026-11-08 试跑）：pi 用官方 uni-preset-vue#vite 模板完成脚手架→改首页→H5 与微信小程序双端构建，协调者直读磁盘验收全过。关键读数：npm install 944 包约 2 分钟；build:h5 4.4s 产物 192K、build:mp-weixin 3.1s 产物 128K；官方预设模板自带样式极素（空架子定位），长相取决于组件库与 tokens，框架本身只决定多端编译能力。

## 关 1：路线判定 + 类目预检（与 5 题同轮定死）

- 目标端含小程序（微信/支付宝/抖音等任一），或需小程序+H5+App 多端同发 → uni-app 路线。
- Web 后台/前台、原生 App（Expo/RN）不走本文件，各按其路线（Astryx / 手写 / 原生生态）。
- **类目预检（硬门槛）**：判定同轮先查目标平台类目可过审性——类目是否开放、需何资质、是否需备案；结论写进 brief.md。类目过不了审（如占卜类目之于微信小程序）不进本路线，改走 H5/公众号等形态，不许做完才发现上不了线。

## 关 2：出样口径 + 插件市场可选步

- 出样照主线（静态首屏定风格）；简报写明小程序实现约束：不用网页专属特效，动效以小程序可实现的 transform/opacity 类为准。
- **可选步：插件市场先逛（仅用户点选才走）**：到 DCloud 插件市场按品类搜候选（整套模板/功能插件），列候选表（名称/价格/Vue3 支持/最近更新/下载量/授权）给用户选。筛选硬门槛：支持 Vue3、近一年有更新、授权允许商用，缺一淘汰；付费项另行经用户批准。不点选即跳过，执行者不许自行引进市场模板充数。

## 关 3：锁定对象

- tokens 照主线锁定，落地形态为 `uni.scss` 变量 + 页面级 CSS 变量；尺寸单位用 rpx，换算口径写进锁定表。
- 同时锁定**组件库选型**（uview-plus / uni-ui / Wot Design Uni 等三选一，写明版本）：组件库即本路线的设计系统，选定后不许混搭第二套。走了插件市场可选步的，引进清单与版本一并记进锁定表。

## 关 4：实现规矩（硬规矩）

- 栈：官方模板 `uni-preset-vue#vite`（Vue3 + Vite），依赖线随模板锁定（试跑基线 `@dcloudio/* 3.0.0-5030420261029002`）；升级先小试、验过再换，不跟随 latest。脚手架落仓库根目录；degit 对非空目录拒绝（exit 1），绕法为先落临时子目录再平铺，**不许 --force**（会清空目标目录）。
- 组件优先：锁定组件库有现成组件的部位必须用组件；手写替代逐个列明部位与原因进交付报告，无清单视为未按轨道执行。
- 多端纪律：平台差异只许用条件编译（`#ifdef`）收敛一处，不许整页复制多份；接口层与页面层分离，后端接口按端无关设计；`pages.json` 为路由单一事实源。
- 市场引进项以 uni_modules 形式锁定版本、记进组件清单。

## 关 5：验收口径

- 截图以 H5 构建产物为准（手机宽度渲染），先行验收样式与数据自洽。
- 另交各目标端构建产物核查：构建命令 + 退出码 + 产物目录（mp-weixin 抽查 app.json/pages 结构与关键页面 wxml）。构建不过不算交付。
- 加一项读数：**主包体积**（微信主包上限 2MB，只报告、逼近上限点名）。引进市场模板的，另查其演示数据/死代码清净与体积增量。
- 开发者工具/真机预览属关 6 上线前环节，不替代本关产物核查。

## 关 6：上线加查

类目资质与备案（与关 1 预检对账）、隐私协议与用户信息收集声明、内容安全（用户输入过平台内容安全接口）、服务器域名白名单与 https、包体积与分包合规。上线走目标平台开发者工具上传 + 平台审核；被拒把拒因原文记进 review，再走修改单循环。

## 不走本路线的边界（写死）

- 类目过不了审的项目不走（见关 1 预检），不许用「先做出来再说」绕过。
- 与 Astryx 路线不重叠：Vue 小程序 vs React Web 后台，各管一摊，不互相借组件。
- 现有单文件 H5、Expo 等既有项目不迁移；要试只在新项目。
