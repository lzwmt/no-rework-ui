# 关 5 修改单循环与关 6 审查

关卡要点在 `gates.md`。修改单填空用 `../templates/change-request.md`。本文件是关 5、关 6 的全文。

## 关 5 每版交付

每版交付必须带：桌面 + 手机（默认 390x844）双截图 + 页面文字重读核对。

产物：每轮 `reviews/review-vN.md`，内容是截图 + 清单 + 结论。

## 关 5 构图验收（每版必做）

- 答 `composition.md` 第六节问答，逐题写「是 / 否 + 一句理由 + 证据」。证据 = 密度读数、检测计数或截图坐标（见 `density.md` 第四节）；只写「是」无证据的答案无效，按未查处理。任何一个「否」，都是本轮修改单的第一条。
- 密度校验（必跑）：按 `density.md` 第三节写 density-layout.json 并跑 `scripts/density_check.py`，density.json 原文附在本轮 review 后。任一格 FAIL 即本轮不合格；自查中出现过的 FAIL 与修复动作必须留痕，不许只报最终全 PASS 的版本。
- 标签碰撞检测：用脚本取图表标签、图例与线、相邻元素的包围盒，重叠数必须为 0。
- 数字反读：从渲染后的页面读出每个数字，与数据源逐项比对，并列出勾连关系的验算过程。
- 与标杆并排截图：比标杆空、平、小，就先修这一条。
- 4b 物料：展示宽度和 358 宽的联系表、封面帧，以及 Stageshow 影片闸门的结论；视频用 ffprobe 核对尺寸、时长、编码、有无音轨。
- 执行本技能的 agent 只能做内部自修一轮，修改单和过关由用户拍板，不代批。

## 修改单

用户用修改单提意见，不说「不好看再改改」。

- 一轮只改一类：先版式 → 再配色 → 再细节，不要混在一轮。
- 一轮 ≤5 条（不超过 5 条，超过拆两轮）。
- 指明基于哪个版本。
- 列「不要改」清单。锁定项不许动，除非用户明确说「解锁改 X」。
- 说不清时：截图圈出来 + 「这里太挤/太空/看不清」，比「高级一点」有效 10 倍。

避坑词（写修改单时用）：别说高级、大气、好看、现代一点。改说留白加大到 24px、标题加大一号、主色只用在按钮上、参考这张图的排版密度。字号意见由执行本技能的 agent 按 `type-and-tokens.md` 译成档位。

## 回执

Agent 改完回：新截图 + 逐条对应清单 + 明确没改什么。对不上不算交付。

新截图包含本关要求的桌面 + 手机（默认 390x844）双截图，并做页面文字重读核对。微调快车道的回执按下面专节，不套这三件的普通格式。

## 版本

`name-v1 / v2 / v3` 另存不覆盖，定版标母版；回退随时能回到上一版。

返工模板的写法是：`name-v1.html`, `name-v2.html`... 永不覆盖母版；定版标 `-final` / 母版。两处都是另存、不覆盖。

## 循环上限

默认 2-3 轮，超了先停下问「是方向错了还是细节没完」——方向错回关 2，不要在细节里打转。

## 微调快车道

字号/间距/颜色这类小细节专用，免走整轮修改单。满足全部三条才走：

1. 不超过 3 处
2. 只动字号档/间距/字重/颜色中的一类数值
3. 不动版式结构、不解锁方向

提法示例，一句话即可：

```
微调，基于 v3：正文 body 升一档（14→16）；区块标题不突出，升一档（20→24）；其他不动。改完只给我手机版前后对比截图。
```

Agent 回：前后对比截图（同尺寸同位置）+ 改了哪几个 token/组件 + 溢出检查结果。快车道改的若是 token，同样记入 `CHANGELOG-UI.md`，不因为小就无账。字号变大后按 `type-and-tokens.md` 用手机 390 宽复查不溢出、不截断、按钮文字不换行挤压。

快车道话术把这一轮的图收成手机版前后对比。普通修改单仍然要桌面 + 手机双截图。两条按各自原文执行。

## 评审小测试

借自 Oil UI 的公开评审方法。三条都做：

1. 三秒测试——首屏缩到 480px 宽（手机图缩到 180px）看三秒，再看遮字版三秒，说得出它是哪类产品、第一眼看到什么，说不清即主角/主动作失败。
2. 换皮测试——把产品名换成无关产品，首屏若仍原样成立，就是套模板（沿用高效品类基线的工具/后台页不算换皮，看核心业务关系与异常焦点）。
3. 缩略认得出——缩到 480px 仍认得出作品特征（工具/后台页则看表面秩序是否干净、业务重心是否一眼可辨）。
